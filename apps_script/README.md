# 반응 버튼 웹앱 배포 (한 번만, 약 10분)

메일 논문 카드의 **[더 보고 싶음] [유용함] [관심 밖]** 버튼이 가는 곳이다. 코드는 `feedback_webapp.gs` 하나이고,
시트 하나에만 쓰며 외부로 요청을 보내지 않는다. 설계 이유는 `../feedback_links.py` 모듈 설명과 `docs/AGENT_PLAN_2026-09-14.md` §2.

## 준비

- 발송용 Google 계정(권장: 2단계 인증 켜기).
- 비밀키 하나: 터미널에서 `python3 -c "import secrets; print(secrets.token_urlsafe(32))"` — 출력값을 아래 두 곳에 **같은 값**으로 넣는다.
  이 값은 채팅·메일·코드에 붙여넣지 않는다.

## 순서

1. Google Drive 에서 **새 스프레드시트** 생성(이름 예: `paper-harness feedback`).
2. 시트 메뉴 **확장 프로그램 → Apps Script**.
3. 편집기의 `Code.gs` 내용을 지우고 `feedback_webapp.gs` 내용을 붙여넣는다.
4. 왼쪽 **프로젝트 설정(톱니)** → "편집기에서 appsscript.json 매니페스트 파일 표시" 체크 → `appsscript.json` 을 이 폴더의 파일 내용으로 바꾼다.
5. **프로젝트 설정 → 스크립트 속성 → 속성 추가**: 이름 `FEEDBACK_HMAC_SECRET`, 값 = 준비한 비밀키.
6. **배포 → 새 배포 → 유형: 웹 앱** — 실행 사용자: **나**, 액세스 권한: **모든 사용자**(받는 분이 로그인 없이 누를 수 있어야 한다) → 배포 → 권한 승인
   (요청 권한은 "이 스프레드시트만"과 "스크립트 서비스 URL" 둘뿐이어야 한다. 그보다 넓으면 멈추고 알려준다).
7. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사.
8. paper-harness 의 `.env` 에 두 줄 추가:
   ```
   FEEDBACK_WEBAPP_URL=<7 의 URL>
   FEEDBACK_HMAC_SECRET=<준비한 비밀키>
   ```
9. 확인: 브라우저로 웹 앱 URL 만 열면 "링크가 올바르지 않습니다." 가 나와야 정상이다(토큰 없음).

`.env` 에 두 줄이 들어간 다음 날 새벽 메일부터 버튼이 붙는다. 두 줄이 없으면 버튼 없이 예전처럼 나간다.

## 버튼을 누르면 (2026-09-16)

기록한 뒤 안내 페이지에 **"탭 닫기" 버튼**이 하나 있다 — 누르면 그 탭이 닫힌다(웹메일에서 연 탭 기준). 페이지가 **스스로** 닫히게는 못 한다:
Apps Script 는 이 페이지를 구글의 샌드박스 iframe 안에 띄우고, 그 iframe 은 사용자가 페이지 안에서 직접 클릭했을 때만 바깥 탭을 닫게
허용한다(`allow-top-navigation-by-user-activation`). 실측(2026-09-16, 웹메일): 자동 닫기는 안 됐고 버튼은 된다. 브라우저가 닫기를 거부하면
버튼 아래에 Ctrl+W 안내가 뜬다. 메일 규격상 "탭이 아예 안 열리게" 하는 방법은 없다(HTML 메일은 링크 클릭만 가능하고 백그라운드 요청을 못 보낸다).

## 화면이 안 바뀌게 하려면 (2026-09-16 사용자 결정)

탭이 아예 안 열리게 하는 길은 Gmail 전용 원클릭 액션(발신=수신 같은 Gmail 계정 + 200 응답 엔드포인트 + 논문별 3버튼 미확인)뿐이라 접었다
(조사 `data/codex_research_2026-09-16/mail_button_no_tab.md`). 대신 브라우저 확장 **Force Background Tab**(Chrome 웹스토어, 새 탭이 포커스를 안
가져감, 데이터 미수집 표기)을 쓴다 — 버튼을 눌러도 보던 메일이 그대로고 기록은 뒤에서 끝난다. 쌓인 탭은 "탭 닫기" 버튼이나 나중에 몰아서 닫는다.
확장의 규칙 설정에서 우리 웹앱 주소(script.google.com)만 백그라운드로 두면 다른 링크의 동작은 안 바뀐다. 우리 코드 변경은 없다.

## 코드를 고치면

Apps Script 편집기에서 **배포 → 배포 관리 → 편집 → 버전: 새 버전** 으로 다시 배포해야 URL 이 그대로인 채 반영된다.

## 회사 PC 확인

회사망에서 `script.google.com` 이 막혀 있으면 회사 PC 에서는 버튼이 동작하지 않는다. 배포 뒤 회사 PC 브라우저로 9 번 확인을 한 번 해 본다.
