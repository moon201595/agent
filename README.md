# paper-harness

관심 분야의 최신 논문을 **매일 알아서 찾아 읽고 정리해 메일로 보내는** 연구 모니터링 에이전트다. 사용자는 처음 키워드만
정하고, 그 뒤로는 메일 속 논문에 반응 버튼(더 보고 싶음 · 유용함 · 관심 밖)만 누른다. 검색어와 키워드 가중치는 그 반응을 따라
스스로 조정된다. 반응은 드물고 메일에 보여 준 논문에만 달리므로, 그것만 믿지 않고 **주 1회 에이전트가 동향과 검색 바깥을
조사해** 조정을 제안한다. LLM 은 제안·판정·서술만 하고, 적용 여부는 Python 규칙이 정한다. 모든 자동 변경은 revision 으로
남고 되돌릴 수 있다.

> 개인 연구용 프로젝트다. 무료 API 와 구독 CLI(Claude Code·Codex)만으로 돈다 — 추가 결제를 해법으로 쓰지 않는다.

## 하루와 한 주

```text
평일 05:00 KST (주말·한국 공휴일은 쉰다)
  run_daily_scan.sh
   ├─ 그 주 첫 근무일이면: DB 보존 정리 → 외부 정찰 → 주간 관리(키워드·검색어·제외어 조정)
   ├─ 그다음 근무일이면: 전날 끝나지 않은 주간 관리를 한 번만 다시 (--catch-up)
   └─ run_profile_scan.py --all --send
        반응 반영(가중치) → ① 검색 → ② 선별 → ③ 본문 → ④ 요약 → ⑤ 수치 대조 → ⑧ 저장 → ⑨ 메일
                                                       └ ⑦ 코드 재현(격리 컨테이너, 비동기)
```

⑦ 은 저장 직후 따로 돌지만, 메일은 오늘 보낼 논문의 재현 결과를 논문당 최대 60분(`batch_summarize.REPRO_WAIT_SECONDS`) 기다린다.
넘으면 이유를 적고 보낸다 — 메일이 늦으면 먼저 볼 곳이다.

- **매일 메일** = 오늘의 연구 흐름(여러 논문을 잇는 서술) + 핵심 논문 카드 5편(원문 분석 / 초록 기반 표시).
- **주간 관리일 메일** = 위에 더해 "이번 주 브리프": 7일 창, 자리 밖 후보, 외부 정찰 결과, 검색 기준이 어떻게 바뀌었나.
- 반응으로 가중치가 바뀐 날은 그날 메일에 한 줄로 알린다.
- 단계 번호 ①~⑨ 는 코드·문서 전반의 이름이다. ⑥ 사람 판단은 승인 관문이 아니라 열람 화면이다.

## 누가 무엇을 정하는가

| 주체 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| 사용자 | 최초 키워드, 메일 반응 | 매번 검색어 지정 |
| Python (결정적) | 검색·순위(튜플 계약)·수치 대조·가중치 조정·제안 검증과 적용·링크 감사 | 글쓰기 |
| Claude (헤드리스, 도구 없음) | 주간 조정 제안, 외부 정찰 결과 검증 | 적용 |
| Codex (헤드리스) | 주간 제안 최종 판정, 외부 정찰·성능 외부 비교(웹 검색), 동향 서술 1순위 | 적용 |
| Gemini → Groq (무료 API) | ④ 논문 요약, 동향 서술 대체 | 판정 |

**반응 → 가중치**(`feedback_weights`, 매일): 서로 다른 논문 2편 이상에 반응이 있어야 키워드 하나가 움직인다. 반응은 반감기
90일로 줄어든다. LLM 을 쓰지 않는다.

**주간 관리**(`agent_maintenance`): Python 이 관측·반응·동향을 근거 ID 가 붙은 브리프로 만들고 → Claude 가 제안 → Codex 가
판정 → `validate` 가 하나씩 근거와 대조한다. 예: 근거로 부른 글에 그 용어가 실제로 있어야 하고, 우산어·기존 키워드의 하위
표현은 받지 않으며, 사용자가 정한 키워드는 지우지 못한다(하향만 된다). 두 모델이 동의해도 이 규칙을 못 넘는다.

**외부 정찰**(`external_scout`, 주 1회): 검색 소스 바깥(학회·리더보드·HF·GitHub)에서 중요한 연구를 찾고, S2(실패하면 arXiv) 공식
기록으로 신원을 확인한 뒤 "그 시점 스캔이 놓쳤는가"를 판정한다. 정찰 모델의 평가·순위는 버린다. 외부 근거만으로 키워드를 더하려면 실제로
놓친 서로 다른 논문 2편 이상이 있어야 하고, 사용자가 관심 밖으로 표시한 내용과 겹치면 안 된다.

**동향 서술**(`trend_report`, story-v2): 모델은 글이 아니라 구조(JSON)를 낸다 — 같은 문제를 다루는 논문 2편 이상을 묶은 흐름,
우리 연구에서 볼 것, 주변 신호. Python 이 인용 근거·태그·카드 포함 여부를 검증하고 제목을 붙인다. 자료에 없는 숫자는 경고 줄을 달고, 초록 근거만 단 결과 수치에는
"(초록 기준)" 을 붙인다.

**성능 동향**(`research_frontier`): 논문 표에서 결과를 모아 관측 DB 에 쌓고, 하루 최대 2편만 외부 근거와 대조한다. 같은 벤치마크·지표로
척도를 맞출 수 있을 때만 관측값끼리 견주고, 그 결과도 SOTA 가 아니라 "관측 범위 내"로만 말한다. 인용·공식 저장소·HF 같은 채택 신호(`adoption_signals`)는 성능과 섞지 않는다.

## 안전장치

- 외부 논문·PDF·링크·저장소는 **비신뢰 입력**이다. ⑦ 재현 컨테이너는 네트워크 없음·권한 제거·읽기 전용·자원 상한으로 돈다.
  논문 속 지시문은 데이터로만 다룬다(`injection_scan` 이 표시한다).
- 주간 관리의 두 모델은 도구 없이 돈다(브리프에 비신뢰 논문 글이 들어가므로). 자식 프로세스에는 허용 목록의 환경변수
  (HOME·PATH·언어·USER·CLI 설정 경로)만 넘긴다. 웹 검색은 외부 정찰과 성능 외부 비교에서만 켜고, 정찰이 찾은 논문은 S2(실패하면
  arXiv) 공식 기록으로 신원을 다시 확인한 것만 쓴다.
- 메일 링크는 SMTP 직전에 한 번 더 감사한다(`link_policy.audit_mail`) — 허용 호스트, DNS 공인 주소, doi.org 리다이렉트 추적.
  막힌 링크는 글자로 남기고 메일은 보낸다.
- 반응 버튼은 HMAC 서명·만료 토큰이고, 외부(Apps Script)에는 무작위 id·버튼 종류·만료 시각만 간다 — 어느 논문·수신자인지는 로컬 DB 에만 있다.
  메일 보안 스캐너의 선열람은 시각 패턴으로 거른다.
- 주간 관리·동향 서술·재현 같은 보조 단계가 실패해도 아침 메일은 나간다. 검색 소스가 **전부** 실패한 프로필은 보내지 않는다 —
  "논문 0편" 메일이 "조용한 날"과 구분되지 않기 때문이다(종료코드 1). 한 소스만 실패하면 보내고 종료코드 2 로 남긴다.
- 시크릿(`.env`)은 코드·로그·메일·LLM 입력에 넣지 않는다.

## 설치·실행

Python 3.14, WSL2 Ubuntu 에서 운영한다.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python migrate.py            # 운영 DB 스키마 대조 (적용은 --apply, 자동 백업)
.venv/bin/python -m pytest             # 전체 테스트 — 인자 없이 돌려도 안전하다
```

환경변수 이름과 발급처는 [docs/API_KEYS.md](docs/API_KEYS.md). 자주 쓰는 진입점:

| 하고 싶은 것 | 명령 |
| --- | --- |
| 매일 운행(cron·Windows 작업 스케줄러가 부른다) | `./run_daily_scan.sh` |
| 프로필 하나를 메일 없이 수동 스캔 | `.venv/bin/python run_profile_scan.py <프로필> --max-pages 30` |
| 주간 관리를 손으로 | `./run_weekly_agent.sh` (브리프만: `agent_maintenance.py --brief-only`) |
| 운영 화면(127.0.0.1 전용) | `.venv/bin/streamlit run review_app.py` |
| 저장 요약 회귀 기준선 | `.venv/bin/python eval.py` |
| MCP 도구(탐색·디버깅용) | `claude mcp add paper-harness -- <절대경로>/.venv/bin/python <절대경로>/server.py` |

개발 환경(VS Code·WSL)과 실제로 겪은 함정은 [docs/SETUP.md](docs/SETUP.md).

## 현재 상태와 한계 (2026-10-01)

- 무인 메일은 2026-08-28 부터, 반응을 따라가는 에이전트 구조는 2026-09-14 부터 돈다. 프로필 4개(각 5편)가 평일마다 돈다. 전체 테스트 1,367개 통과.
- **반응이 드물다.** 지금까지 5건(모두 "더 보고 싶음", 9/16·9/20)이고 9/21 부터는 없다. 주간 키워드 변경 적용 5회 중 반응을
  근거로 한 것은 1회, 나머지는 동향 근거였다 — 반응만으로는 프로필이 움직이지 않는다는 설계 전제가 운영에서 그대로 나타났다.
  "관심 밖" 반응은 아직 없어 하향 적응은 실측되지 않았다.
- **외부 정찰은 실측 전이다.** 저장 표가 2026-10-01 에 운영 DB 에 적용됐고, 첫 정규 실행은 다음 주간 관리일(2026-10-06) 예정이다.
- 본문은 arXiv·오픈액세스만 받는다. 유료 저널은 초록 기반으로 정리하고 카드에 그렇게 표시한다.
- 동향 서술을 대체 엔진(Gemini)이 쓰면 목표 길이보다 길어지는 경우가 있다.
- 수치 대조(⑤)는 문자열 대조다 — 의미상 정확성을 보증하지 않는다.

## 라이선스·데이터 주의

의존성은 `requirements.txt` 에 있다(mcp·httpx·pypdf·beautifulsoup4·streamlit·holidays). PyMuPDF 는 AGPL 이라 일부러 쓰지 않는다 —
의존성을 더할 때는 라이선스를 먼저 확인한다. arXiv 논문 대부분은 재배포 권한이 없는 기본 라이선스다. 내려받은 본문·추출 텍스트
(`data/`)는 저장소에 올리지 않고 외부로 재배포하지 않는다.
