## 3. 설계

### 3.1 변화 판정 — relation 이 아니라 "지난 동향 설명 ↔ 지금 사슬 근거" 비교 (v2)
- v1 의 "expanding/branching 이면 변화, continuing 이면 변화 없음" 은 버린다. relation 은 한 단계 비교라 거짓 변화(작은 흐름 대비 확장이지만 동향 전체로는 이미 있던 방향)와
  누락(continuing 이 이어지며 서서히 틀어짐)이 생기고, 연결 누락을 "변화 없음" 으로 바꾼다. relation 은 **참고 입력**으로만 준다.
- 판정은 동향 서술 호출에 합친다(호출 수 그대로). 주제마다:
  `{chain, decision: changed|unchanged|uncertain, before, after, evidence_after: [노드 ID], change_text, reason}`
  - 입력: 기준 스냅샷의 방향 설명(맥락 — 근거 아님), 기준 이후 새로 붙은 노드의 이름·논문 제목·(가능하면 저장된 초록 한두 문장)·relation(참고).
  - `changed` 는 `before`·`after`·`evidence_after`(기준 이후 노드만)·`change_text` 필수. 근거가 제목뿐이라 판단이 안 서면 `uncertain`.
- Python 검사: 주제 번호·기준 스냅샷 ID 일치, `evidence_after` 가 그 주제의 **기준 이후** 노드인지, 결정값, 한국어·숫자(`_accept` 계열).
  창에서 노드가 빠진 것만으로는 `changed` 를 받지 않는다(새 노드가 없으면 판정 호출 자체를 하지 않는다 → `unchanged`).
- 이것도 **해석**이다. 메일의 변화 문장에는 지금처럼 "(해석)" 성격을 안내문에 밝힌다. 실제 정확도는 사람이 기대 판정을 붙인 사례로 따로 잰다(미실측).

### 3.2 주제 대응 (v2)
- 노드 주소에 **내용 지문**(흐름 이름 + 논문 제목 정렬 해시)을 함께 둔다 — 같은 주소의 내용이 재실행으로 바뀌면 다른 노드다.
- 표시 상한(4개)보다 먼저 **모든 유효 사슬**을 계산해 대응하고, 상한은 그다음에 적용한다 — 상한에 밀렸다 돌아온 주제를 "새 주제" 로 부르지 않는다.
- 대응 종류를 가른다:
  - 일대일(노드 공유) → 같은 주제, 본문 이어 씀.
  - 일대다(창 이동으로 갈라짐) → 각 갈래는 **본문을 다시 구성**(같은 본문 복사 금지). 구조 분리는 방향 변화가 아니므로 꼬리표는 "변화 없음" 또는 판정 결과.
  - 다대일·동률 → 본문 다시 구성 + "비교 보류". 임의 상속 금지.
- 주제 지속 ID(`topic_id`)를 새로 주고 스냅샷에 남긴다. 날짜·순번·제목만으로 대신하지 않는다.
- 사라진 주제(B): 메일에 알리지 않는다(창 밖·상한·자격 미달은 방향 변화가 아니다). 내부 기록은 유지.
- 잠잠함(I): 변화로 부르지 않는다. 휴일·검색 실패·서술 실패로도 관측이 빈다. 표시는 "마지막 관측 MM/DD".

### 3.3 상태 (v2)
| 상태 | 조건 | 제목 아래 상태 줄 | 본문 |
|---|---|---|---|
| 새 주제 | 대응하는 지난 주제 없음(이 메일 동향에 처음 들어옴 — 분야의 신생 주제라는 뜻 아님) | 새 주제 | 전체 서술 |
| 변화 | 판정 `changed` 통과 | 변화 · MM/DD | 기본 설명 + **이번 변화 문장만 굵게** |
| 변화 없음 | 새 노드 없음, 또는 판정 `unchanged` | 변화 없음 · 마지막 관측 MM/DD | 기본 설명 그대로(+ 지난 변화 기록 보통 글씨) |
| 비교 보류 | `uncertain`, 판정 실패, 기준 조회 실패, 다대일 대응 | 비교 보류 · 마지막 관측 MM/DD | 기본 설명 그대로 |

- 조회 실패 ≠ 기록 없음(새 주제 아님), 판정 실패 ≠ 변화 없음, 관측 없음(오늘 서술 실패) ≠ 변화 없음 — 모두 "비교 보류".
- 경과 줄: 새 날짜는 그대로 덧붙이고 **`changed` 의 `evidence_after` 칸만 굵게**. 같은 방향으로 붙은 날짜는 굵게 하지 않는다.

### 3.4 본문 구성과 재작성 (v2)
- 본문 = **기본 설명** + **날짜가 붙은 변화 기록**(`[{date, text}]`) + 이번 메일 강조 구간. 굵게는 이번 비교의 변화 문장만.
- 변화 문장은 "10/22 논문부터 ~ 쪽으로" 처럼 **날짜로** 쓰게 한다("오늘"·"최근에는" 금지) — 다음 날 보통 글씨로 남아도 시점이 틀리지 않게.
- 기본 설명 재작성은 **편집 사건**이고 변화 판정과 독립이다. 재작성해도 그날 `changed` 의 굵게는 유지한다. 재작성 시점:
  주간 관리일, 일대다·다대일 대응, 기본 설명이 부른 논문이 모두 창 밖으로 나갔을 때, 변화 기록이 3개를 넘을 때(기록을 기본 설명에 흡수).
- 재작성 실패 → 이전 글 유지 + 내부에 "재작성 미완료" 로 남겨 다음 날 다시 시도. 성공하지 않은 재작성을 완료로 기록하지 않는다.
- 판정 기준(`before`)은 **기준 스냅샷의 방향 설명**이다. 매일 기준을 조금씩 옮겨 누적 변화를 놓치지 않도록, 기준 방향은 `changed` 가 확정될 때만 갱신한다.

### 3.5 저장 — 새 표 `research_trends` (v2, v1 의 (가) 폐기)
- (가) kind 추가는 `agent_trend_evidence` 에 자동으로 섞인다(위 2절). 별도 표로 둔다: schema_guard DDL + migrate.py 등록(`--apply` 백업 경로).
- 행: `(profile_id, reader_date, snapshot_id, created_at, status: candidate|sent, payload_json)`.
  payload: 주제마다 `topic_id, nodes[(narrative_id, thread_index, 지문)], title, base_body, base_direction, changes[{date,text,evidence}],
  state, decision, last_observed, rewrite_pending`.
- **독자 기준은 실제로 발송한 스냅샷**이다. 생성 직후 `candidate` 로 저장, 그 프로필 메일이 한 명에게라도 SMTP 성공하면 `sent` 로 확정(mail_ledger 성공 기록과 같은 자리).
  비교 기준 = reader_date < 오늘 중 최신 `sent`. 발송 뒤 수동 재실행·SMTP 실패 후보가 기준을 덮지 않는다. 같은 날 `sent` 가 이미 있으면 후보는 기준이 되지 않는다.
- `narrative_store.save` 반환값을 실제 저장된 narrative_id 로 고친다(지금 쓰는 곳은 없지만 이번 구현이 쓰게 된다).

### 3.6 호출 위치와 실패 경로 (v2)
- 동향 단계를 `if story:` 밖으로 뺀다 — 오늘 서술이 실패해도 저장된 동향으로 "비교 보류" 상태로 싣는다. 빈 메일(오늘 논문 0편)에도 동향 절을 낼지는 사용자 확인(쟁점 J).
- 시간 상한은 동향 단계 전체(대응·판정·재작성·저장)에 건다(지금 900초는 narrate 에만).
- 렌더 국소 폴백: 동향 자료가 깨져도 HTML 전체가 실패하지 않게 `research_trends_html` 을 try 로 감싸 경과만 그린다(scan_deliver 는 HTML 실패를 발송 실패로 친다, scan_deliver.py:124).

### 3.7 평문 표지 ↔ HTML (v2)
- 상태는 제목 줄에 붙이지 않고 별도 줄: `     상태: 변화 · 10/22` (제목의 "—" 를 쪼개지 않는다).
- 변화 문장: 본문 줄 앞에 `     [이번 변화] ` 표지. 문단 하나 전체가 아니라 변화 문장만 그 줄에 둔다.
- 경과 강조: `경과: 10/08 A → [변화] 10/22 B` 처럼 **정해진 경과 항목 문법**(일반 마크다운 `*` 변환 금지 — 이름 속 별표와 충돌).
- 제어 표지 escape: 모델 글이 `▸ `·`경과: `·`상태: `·`[이번 변화]` 로 시작하면 앞에 공백 문자를 넣어 표지로 읽히지 않게 한다.
- HTML: 텍스트 escape 뒤 강조 구간만 `<strong style="font-weight:700">`, 상태 글자도 남긴다. 실제 메일 클라이언트 표시는 미실측 — 시험 발송으로 확인.
- 옛 저장 메일(표지 없음)은 지금처럼 그린다. "이 메일 읽는 법" ① 에 상태 네 가지와 굵은 글씨 뜻 한 줄 — 표지가 있는 메일에만.

## 5. 남은 쟁점
- J. 오늘 논문이 0편인 날에도 동향 절을 실을지 — **사용자 확인**(Claude 추천: 싣는다, 상태는 "비교 보류" 아닌 "변화 없음 · 마지막 관측").

- L. 시험: 지난 3주 저장 서술로 날마다 다시 돌려 상태 분포(새 주제·변화·변화 없음·보류)를 보고, 사람이 변화 판정 몇 건을 확인한다.
