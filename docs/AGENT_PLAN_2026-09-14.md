## 3. 피드백 기반 자동 가중치 — "따라가되 흔들리지 않게"

**반응값**: 더 보고 싶음 +1.0 · 유용함 +0.7 · 관심 밖 −1.0. 한 회차·한 수신자·한 논문은 최신 반응 하나만.

**특징**: 그 논문의 core 적중 키워드 · domain 적중 · 새 용어(`term_hygiene.ngrams`) · 모델명/태스크명 · 들어온 시드. 한 논문의 신호는
특징 수로 나눠 배분(넓은 키워드가 모든 반응을 독식하지 않게).

**갱신식 — Codex 안을 고쳐서 채택**: Codex 안은 매일 `weight += η·signal` 이라 **새 반응이 없어도 같은 증거로 매일 계속 오른다**
(누적 표류). v2 는 **목표값을 따라가는 방식**:

```text
signal(f) = (pos(f) − neg(f)) / (pos(f) + neg(f) + κ)          # κ = 4 (2명 규모 — 운영 시작값)
target(f) = clamp(base(f) + A · signal(f), 0.35, 2.0)            # base = 사용자가 처음 준 가중치(새 키워드는 0.4), A = 0.8
weight(f) ← weight(f) + clamp(target(f) − weight(f), −0.1, +0.1) # 하루 최대 0.1 이동
pos/neg 는 반감기 90일로 감쇠
```

예: 서로 다른 논문 3편에 "더 보고 싶음" → signal = 3/7 ≈ 0.43 → target = base + 0.34 → 3~4일에 걸쳐 도달. 새 반응이 없으면 target 에
머물고, 시간이 지나 감쇠하면 base 로 서서히 돌아온다.

**새 키워드 자동 추가**: 긍정 논문의 후보 용어가 **서로 다른 논문 2편 이상**에서 긍정 → core 에 가중치 0.4 로 추가(`origin=feedback`).
4주 동안 추가 긍정 없고 음수면 비활성. **사용자 최초 키워드는 자동 삭제하지 않고 하향만**(Codex 쟁점 3 — 합의).

**순위 결합**(Codex 쟁점 2 — 합의, 이중 계산 주의):

```text
rank_key = (−feedback_band, weight_band, −날짜, −적중 폭, −도메인, −연속 가중치, 키)
feedback_band ∈ {2: 최근 긍정 논문과 특징 2개 이상 공유 또는 S2 추천 출처, 1: 1개, 0: 없음, −1: 부정 논문과 2개 이상 공유}
weight_band   = 가중치를 0.25 폭 구간으로 묶은 계층 (연속값이면 계층이 수십 개로 쪼개져 최신성이 무시된다 — profile_scoring.tier_rank 가
                서로 다른 가중치 값마다 계층을 만든다)
```

**"비슷한 논문 더 보기"**: Semantic Scholar Recommendations API(긍정/부정 논문 ID → 추천) 를 검색 소스로 추가 — **엔드포인트·무료 여부는
구현 첫날 1회 실측해 확인**(추측으로 의존하지 않는다). 안 되면 긍정 논문의 모델명·방법명으로 S2 검색어 생성.

**모든 갱신은 batch 하나 = revision 하나**(before/after 스냅샷) → 주간 메일에 "이번 주 바뀐 것" + 되돌리기(운영자 화면).

   차단(리다이렉트마다)·스트리밍 크기 상한·시간 상한.
2. **PDF 파서**: 크기·페이지·텍스트 길이 상한, 파싱을 자식 프로세스+시간 제한, 실패 파일 즉시 삭제.
3. **clone·빌드**: clone 전후 크기·파일 수 상한, LFS 끔, build context 를 clone 디렉터리로 한정·`.git` 제거, 호스트 마운트·소켓 금지,
   `launch_background` 의 `bash -c` 문자열 조합 제거(`docker_runner.py:569-614`). **재현은 멈추지 않는다**(Codex 쟁점 4 — Claude 판단:
   실행 단계는 이미 `--network none`·cap-drop·read-only·nobody 라 위험은 빌드 단계 네트워크에 한정되고, context 제한·시간·자원 상한으로 1차
   차단 가능. 오프라인 wheel 캐시 빌드는 2주차).
4. **프롬프트 인젝션**: 논문·README 는 데이터 블록으로 격리, 에이전트 출력은 스키마 검증만 통과, URL·명령·경로는 Python 허용 목록 통과 후
   실행, `injection_suspect` 논문은 에이전트 웹 검색·재현 입력에서 표시.
5. **메일 링크·피드백 위조**: 피드백 링크 HMAC·만료·중복 제거·선열람 격리, 외부 논문 링크는 https·표시 호스트 명시, 첨부 없음.

검증: 위협별 공격 픽스처(사설 IP·리다이렉트 체인·거대/폭탄 PDF·대용량 저장소·인젝션 초록·위조 토큰) 테스트 + 한 달 동안 차단 로그 주간 표시.

## 5. 코드 재현 — "반드시 찾기" 사다리

Claude Code 에이전트(웹 검색 가능)가 순서대로 **전부** 시도하고 중간에 멈추지 않는다: ① 논문 본문 링크 ② 저자·연구실·프로젝트 페이지
③ 제목·모델명·저자 조합 검색 ④ Hugging Face 모델/데이터셋 카드 ⑤ 같은 태스크·방법 구현 ⑥ 후속 논문·참고 구현 ⑦ 그래도 없으면 `찾지 못함` +
시도한 검색어. Codex 가 후보마다 코드 저장소인지·저자 연결·제목/모델 일치·"공식" 근거·실행 가능성을 비판.

## 6. 분야별 SOTA 추적 (2026-09-15 정정 — 사용자 5번)

뜻: "과제 목표를 주면 baseline 추천"이 아니라 **사용자 관심 분야별로 "지금 무엇이 SOTA 인가"를 알려주는 것** — 예: 비전 검사(이상 탐지)에서
어떤 모델이, 로봇 조작(VLA)에서 어떤 용도로 어떤 모델이, VLM·온디바이스 추론에서 무엇이.

**정직한 표현이 핵심**: 메일에는 "현재 SOTA" 단독 표현을 쓰지 않고 **"(벤치마크·분할·지표·프로토콜) 기준 최고 후보 + 근거 등급 + 확인 날짜"**로 쓴다.

- **트랙**: 프로필의 core 키워드 묶음에서 분야·용도·데이터 형태·배포 제약으로 만든다(키워드 하나 = 트랙 하나가 아니다). Python 이 묶음 후보 →
  Claude 가 빠진 트랙·벤치마크 후보 제안 → GPT 가 중복·표기 변형 비판 → **사용자가 한 번 확인한 트랙만 활성**. 벤치마크를 모르면 `benchmark_unknown`.
- **비교키**: 트랙 · 용도 · 데이터셋(+버전) · 분할 · 지표(+방향) · 평가 프로토콜(학습 방식·추가 데이터·앙상블) · 모델 범위 · 기준 날짜.
  비교키가 다르면 최신 논문이라도 승자를 바꾸지 않고 `비교 불가`.
- **근거 등급**: A 공식 리더보드·챌린지(버전·분할·갱신일 확인) · B 벤치마크 공식 보고·독립 평가 서버 · C 논문 결과표의 같은 조건 행(저자 보고값) ·
  D "state of the art" 문장만(판정에 안 씀) · E 블로그·검색 스니펫(후보 발견용만). 리더보드 갱신일이 90일 넘으면 `stale`.
- **자료 결합**: 우리 DB 의 검증 통과 요약 결과 절(원문 비교표 수치)을 먼저 후보로 쓰고(`trend_report.result_excerpts` 조건 재사용), Claude 웹 조사로
  리더보드·최신 논문을 보강한다. 둘이 다르면 덮어쓰지 않고 둘 다 저장. 원문 URL·위치·접근일·내용 해시 없는 수치는 저장하지 않는다.
- **변화 감지**: 스냅숏은 append-only. 변화 유형 new_winner · metric_improved · protocol_changed · evidence_upgraded/downgraded · no_change · incomparable.
- **빈도**: HOT 트랙 매주 · WATCH 월 1 · COOL 분기 1 · 사용자가 "지금 확인" 요청 시 즉시 1회(주간 예산 앞당김). 매일 전체 검색은 하지 않는다.
- **메일**: 주 1회, 트랙당 한 줄·최대 3줄 — 예: "비전 검사 / 산업 이상 탐지 — MVTec AD · 이미지 AUROC · test 기준 최고 후보 Model X(저자 결과표 기준,
  리더보드 교차확인 미완료) [출처]" · "로봇 조작 / VLA — 같은 조건 비교 근거 없음: 이번 주 판정 불가(마지막 확인 날짜)".
- **저장**: `sota_tracks` · `sota_sources`(URL·종류·접근일·해시·등급·위치) · `sota_results`(모델·데이터셋·분할·지표·값·프로토콜·보고 주체) ·
  `sota_snapshots`(비교키 해시·상태·변화 유형) + `sota_snapshot_winners`(공동 최고).
- **분담**: Claude 조사·후보 정리 · GPT 같은 조건인지·자기주장인지·오래됐는지 감사(승자 확정 안 함) · Python 비교키 정규화·지표 방향 비교·스냅숏·메일 3줄.

## 7. 최소 규칙 (새 CLAUDE.md — 기존 규칙 전부 대체)

1. **사용자 피드백이 1순위 신호다.** 최초 키워드는 사용자가 정하고, 이후 조정은 피드백을 따른다. 최초 키워드는 자동 삭제하지 않는다.
2. **LLM(Claude Code·Codex)은 해석·탐색·제안·비판, Python 은 저장·실행·적용.** LLM 출력은 JSON 스키마 검증을 통과해야 쓰인다.
3. **모든 자동 변경은 revision 으로 남기고 되돌릴 수 있다.** 되돌리기 어려운 작업(DB 대량 삭제·스키마 변경)은 백업 뒤에.
4. **외부 논문·PDF·링크·저장소는 비신뢰 입력이다.** 크기·시간 상한, 네트워크·파일시스템이 막힌 격리 환경에서만 처리·실행한다.
5. **시크릿과 사내 문서는 코드·로그·메일·LLM 입력에 넣지 않는다.** `.env` 는 읽지 않는다.
6. **에이전트 단계가 실패해도 아침 메일은 나간다.** 헤드리스 실행은 시간 상한·실패 시 건너뛰기를 갖는다. 추가 결제 없이 운영한다.
7. **없는 것을 만들지 않는다.** 공식이 아닌 코드를 공식으로, 확인 안 된 SOTA 를 사실로 표시하지 않는다. 변경은 테스트 통과 뒤 반영한다.
