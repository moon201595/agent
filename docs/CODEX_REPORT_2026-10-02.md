## 6. 전체 테스트·적용 진행 상태

요청한 `.venv/bin/python -m pytest`를 인자 없이 실행했다. 하지만 이 샌드박스는 socketpair.send조차 `PermissionError: [Errno 1] Operation not permitted`로 막았다. 빈 `asyncio.to_thread(lambda: None)`도 작업 완료 뒤 asyncio.run 종료 단계가 멈췄고 10초 timeout으로 종료됐다. 기존 test_briefing의 본문은 MAIN SUCCESS까지 갔지만 실행기 종료에서 멈췄다. 표적/첫 전체 실행은 중단(exit 130)했다. 이를 코드 회귀 실패나 전체 green으로 기록하지 않는다.

저장소 밖 /tmp/handoff_async_poll/sitecustomize.py에서 이벤트 루프에 50ms 주기 깨우기만 예약해 같은 최소 예제 종료를 확인했다. 태스크 반환값·예외·테스트 기대값은 바꾸지 않는다. `PYTHONPATH=/tmp/handoff_async_poll .venv/bin/python -m pytest`로 pytest 인자 없이 **1,392 passed, 35 warnings, 105.62초, exit 0**을 확인했다. 이 환경 보조 코드는 제품에 반영하지 않는다.

재기동 사전 확인: 현재 PID 공간에서 기존 Streamlit 프로세스가 보이지 않는다. 127.0.0.1:8501 요청도 `curl: (7) failed to open socket: Operation not permitted`다. 자동 승인 거절이 아니라 현재 샌드박스의 시스템 호출 제한이며 권한 확장은 허용되지 않는다. 최종 적용 결과는 아래에 추가한다.

### 최종 재기동 결과

명령행 토큰과 저장소 cwd로 기존 `streamlit run review_app.py` PID를 찾았으나 이 PID 공간에서는 0개였다. 임의 PID나 패턴 kill은 사용하지 않았다. 저장소에서 요청한 명령을 그대로 실행했다.

```bash
setsid nohup .venv/bin/streamlit run review_app.py >> logs/streamlit.log 2>&1 < /dev/null &
```

시도한 프로세스는 exit 1로 종료했다. `logs/streamlit.log` 끝(3181행)에 `_bind_socket → socket.socket → PermissionError: [Errno 1] Operation not permitted`가 남았다. 127.0.0.1:8501 확인도 curl exit 7·HTTP 000이었다. **운영 화면 재기동·적용 성공은 확인하지 못했다.** 기존 호스트 프로세스의 종료·생존 상태도 미확인이다. 권한 있는 호스트 세션에서 기존 PID 종료 후 같은 실행 명령과 HTTP 확인이 남는다.

## 7. 남은 쟁점·미실측

- **적용 미완료:** 현재 샌드박스는 기존 호스트 PID를 볼 수 없고 소켓을 만들 수 없다. 새 Streamlit 인스턴스를 성공적으로 띄우지 못했다.
- **일반 전체 테스트 종료 미확인:** 보조 코드 없는 명령은 asyncio 종료에서 대기했다. 보조 코드를 쓴 전체 1,392개만 green이다. 테스트 35개 경고는 기존 스타일 문자열의 `\m` SyntaxWarning이다.
- **서술 총량 부채:** 목표 1,200자를 초과한 글이 3개이며 모두 Codex다. 현재 프롬프트 목표와 구조 렌더링 사이에 결정적 전체 길이 제한이 없다. 임의 문자열 자르기나 의미 삭제는 적용하지 않았다. 흐름 수·본문·목록을 포함할 예산 정의가 남는다.
- **실제 메일 수신함·브라우저 미실측:** SMTP 결과 로그/DB의 sent와 저장 다이제스트를 확인했다. 수신함 도착·메일 클라이언트 렌더링·실제 브라우저의 히스토리 버튼/배율·스크립트 실행은 측정하지 않았다. URL 탐색은 AppTest로 재현했다.
- **과거 깊이 한계:** 같은 회차 카드가 남아 있으면 그 라벨이 우선이다. 카드가 없는 과거 회차는 기존처럼 현재 요약 coverage·같은 날 저장 서술의 명시값으로 보완하므로 발송 당시의 완전한 스냅숏은 아니다. 회차별 다이제스트 원문/깊이 저장 스키마를 추가하지 않았다. coverage가 미기록인 구형 요약은 화면에서 깊이를 비워두며 메일의 기본 원문 라벨과 다를 수 있다.
- **회차 연결 한계:** last_digest는 회차 ID를 저장하지 않는다. 발송 시각 구간·전체 제목으로 보수적으로 연결했지만 역사적 회차 전체의 정확한 본문 복원은 불가능하다.
- 동일 날짜 순차 재발송 가능성, 10/6 주간 브리프·정찰 및 10/7 따라잡기는 기존 인계의 후속 항목이다. 이번 작업에서 실제 발송/추가 스캔을 실행하지 않았다.
