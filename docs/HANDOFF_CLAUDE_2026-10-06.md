코드 수정 허용 범위: 이번 두 표시 요구와 직접 관련한 digest.py, mail_layout.py, saved_digest.py, 관련 test_*.py. 변경 내용과 독립 검토 지적은 docs/CLAUDE_REVIEW_2026-10-06.md에 절별로 저장한다. 그 밖의 코드에서 발견한 결함은 파일:줄·재현을 보고하고 함부로 고치지 않는다. PROGRESS나 기존 Codex 보고서는 주 도구가 결과 통합 시 기록하므로 이번 Claude 세션에서는 수정하지 않는다.

## 3. 이번 수정·검토 지점

현재 코드로 찾은 문구 위치는 digest.py:_changes_tail(약1587줄)이다. HTML/평문 공통 꼬리에서 hidden 건수를 문구로 출력한다. 그 문구를 표시에서 삭제하고 반영된 사용자 반응의 실제 건수는 남긴다. 가중치 변경/집계/DB revision 자체를 삭제하거나 숨겨진 작은 변화가 없다고 만들지 않는다. 삭제 뒤 구분점이나 빈 제목/빈 흰 박스가 남는지도 확인한다.

기존 test_weekly_profile_changes.py:test_a_week_of_only_small_moves_still_says_so는 앞 문구의 존재를 요구한다. 사용자 요구로 폐기되는 표시 계약이므로 그 기대는 새 요구(문구 없음/실제 반응 유지/데이터 unchanged)에 맞춘 고정 기대로 변경한다. 다른 테스트의 내용/집계/안전성 기대를 약화하지 않는다.

여백은 ‘최근 7일 흐름’의 숫자/상승·하락, ‘핵심 키워드 밖 반복 관측’, ‘자리에 못 든 후보에서 자주 나온 말’부터 외부 정찰·검색 기준 변화·맨 아래 꼬리까지 흰 블록 안쪽에 넣는다. 사용자 첨부에서 흰 블록의 글씨가 왼쪽 경계에 붙어 있다. 바깥 회색폭/본문 폭을 키우지 않고 각 흰 영역 안쪽 좌우12~14px 정도의 여백을 우선 판단한다. 제목/칩/본문도 해당 영역 안에서 경계와 떨어져야 한다. 이전 논문 표의 중앙 정렬/토글/색과 기존 레이아웃은 유지한다. 실제 메일 HTML 생성 경로를 검토하고, 저장 메일 렌더러에 같은 문제나 옛 꼬리 문구가 남는 경우도 표시 단계에서 다룬다. 원 저장 평문/운영 DB를 다시 쓰지 않는다.
