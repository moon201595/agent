# DESIGN.md — 운영 화면(review_app) 디자인 기준

2026-10-01 개정(그전 판 2026-09-16 은 git 이력). **메일이 이 시스템의 얼굴이고 화면은 그 확장이다.** 9/16 화면은 파랑 `#3B5BDB`·Pretendard·
둥근 카드·그림자였고 메일(9/30 시안)은 청록·평평한 상자라, 같은 서비스가 두 제품처럼 보였다. 토큰을 메일(`digest.py` 의 `_ACCENT`·`_INK`·
`_CHIP`)에서 가져와 하나로 맞췄다. 적용 수단은 `.streamlit/config.toml`(테마)과 `review_app._inject_custom_style`(CSS) 둘이다.

## 1. 성격
"연구소 안의 업무 도구". 매일 아침 몇 분 읽는 화면 — 눈에 띄는 것보다 **읽히는 것**이 먼저다. 스타트업 대시보드처럼 보이게 하는 장식
(아이콘 타일·큰 숫자·그림자·둥근 카드)을 쓰지 않는다. 사내 업무 시스템의 밀도(맑은 고딕, 조금 작은 글자, 굵기 두 단계)에 메일의
청록 강조와 정보 순서를 얹는다.

비율은 대략 **흰색 80% · 옅은 회색 15% · 청록 5%**(10/1 외부 의견). 표 머리는 민트가 아니라 `#F8FAFB` + 글자 `#3C4B59` —
민트 머리가 선택 메뉴와 경쟁했다. 입력칸은 흰 바탕 + 테두리(회색 본문 위에서 검색칸이 묻혔다).
강조색은 청록 하나다 — **읽는 순서의 입구에만** 쓴다: 갈래 번호 배지, 오늘의 요점 상자(옅은 청록), 선택된 메뉴, 원문 분석 칩, 펼치기 글자.
본문·표·테두리는 잉크·회색. 상태색은 상태에만, 범주 팔레트는 그래프에만 쓴다.

## 3. 글꼴
`"Malgun Gothic", "맑은 고딕", "Apple SD Gothic Neo", "Noto Sans KR", Arial, sans-serif` — 사내 PC(Windows) 기본 글꼴이고, 메일도
Windows 에서는 이것으로 보인다(메일의 첫 글꼴 Noto Sans KR 이 없으므로). 외부 글꼴을 불러오지 않는다. **기본 16px**(`config.toml`
`baseFontSize` — CSS 가 아니라 테마 옵션이라 표·입력칸까지 같이 먹는다). 2026-10-01 에 외부 의견대로 14px 로 줄였다가 "글씨크기부터 쳐 키워"
지적을 받았다 — 9/17 에도 "글자를 키운다"였다. **줄이지 않는다.** 굵기는 400·700 두 단계. 숫자는 `tabular-nums`. 전역 자간을 주지 않는다
(캔버스 표에 먹어 낱말 사이 빈칸이 사라졌다).

| 역할 | 크기 |
|---|---|
| 개요 큰 제목 | 2.1rem |
| 페이지 제목(h3) | 1.75rem |
| 구역 제목(`.rm-h`, h4) | 1.45rem / 1.22rem |
| 본문·흐름 글 | 1.05rem, 줄 간격 1.8 |
| 사이드바 메뉴 | 1.15rem (브랜드 1.5rem) |
| 캡션·라벨·칩 | 0.85~0.95rem |

## 4. 간격·모양
- 모서리 6px(칩 3px). **그림자 없음.** 테두리 `--line` 1px.
- **본문 폭 제한 없음**(9/16 사용자 결정 — 넓은 모니터에서 비지 않게). 10/1 에 1280px 로 묶었다가 가운데만 덩그러니 남았다. 한 줄 길이는
  상자 안 두 칸 격자로 줄인다(대시보드 본문 권장 45~85자).
- 사이드바 320px(9/16 은 340px, 10/1 에 272px 로 줄였다가 비율 지적). 선택된 메뉴는 연한 청록 배경 + 왼쪽 3px 청록 선.
- **구역은 상자로 묶는다**(10/1 사용자: "카드 안의 카드를 쓰던 분야별로 박스로 묶던 가독성을 높여야") — 시스템 화면은 운영 상태·프로필·DB·실행 기록·
  주간 에이전트·예약 작업·로그가 각각 테두리 상자, 그 안의 숫자는 옅은 바탕 카드(`.rm-stat`). `st.metric` 은 긴 값을 "…" 로 잘라 쓰지 않는다.
- 확인은 **실제로 쓰는 화면 조건**에서 한다 — 2560px 화면·Windows 배율 150%(브라우저 폭 약 1700px). 1440px 캡처만 보고 끝내지 않는다.

## 5. 구성 요소
- **개요의 순서는 메일과 같다**: 눈썹 글(RESEARCH MONITOR · 날짜) → 제목 → 프로필 → 숫자 줄 → 오늘의 연구 흐름 → 오늘의 핵심 논문 →
  이번 주(7일 키워드 흐름·검색 프로필 변화) → 맨 아래 한 줄 운영 상태. 운영 상태(cron·다음 실행)는 첫 줄에 두지 않는다.
- **숫자 줄**: 타일이 아니라 위 2px 잉크 선·아래 1px 선 사이의 칸들(메일과 같다). DB 에 있는 값만.
- **오늘의 요점**(2026-10-06 "오늘의 한 줄"에서 바꿈 — 두세 문장): 왼쪽 3px 청록 선 문단.
- **흐름**: 두 칸 격자(`minmax(380px, 1fr)`, 좁으면 한 칸). 칸마다 번호·이름·본문·논문 목록(깊이 칩). 메일은 한 칸 그대로다 — 메일
  클라이언트(특히 모바일)에서 두 칸은 제목이 긴 영어 논문 목록을 170px 폭으로 접는다.
- **깊이 칩**: 메일 카드와 같은 문구(원문 분석 완료 · 원문 일부 분석 · 초록 기반 · 미검증), 일반 칩.
- **메뉴**: 개요 · 논문 · 프로필 · 활동 기록 · 시스템, 회색 선 아이콘(Material Symbols, 선택만 청록). 프로필 선택은 사이드바 하나.
  **새 프로필 만들기는 프로필 화면 맨 위.**
- **상자는 `st.container(border=True, key="box_…")`** — 테두리가 Streamlit 내부 클래스라 `[style*=border]` 로는 안 잡혔다(DOM 실측). 흰 바탕·구역 제목
  청록 막대는 `.st-key-box_*` 로 준다. 상태 카드는 왼쪽 막대·값 색으로 정상(초록)·실패(빨강)·주의(주황). 표 머리는 옅은 청록(`dataframeHeaderBackgroundColor`).
- **활동 기록은 달력**(사용자 시안 추천안) — 왼쪽 달력(메일 보낸 날 청록 점, 반응 온 날 주황 점, 고른 날 청록 칸) + 월 요약, 오른쪽 고른 날의
  메일·논문 표(키워드 칩·반응 칩). 날짜별 펼침 목록은 가독성이 떨어졌다.
- **소제목과 상자 사이를 띄운다** — 개요 소제목 위 44px·아래 18px, 밑줄 없음(밑줄이 상자에 붙어 보였다).
- **논문 제목 밑에 한국어 제목**(메일과 같다) — 발송 때만 번역되므로 그날 다이제스트 평문에서 읽는다(`ops_dashboard.digest_extras`, API 다시 안 부름).
- **핵심 논문은 메일 카드처럼 접힌 카드**(`<details>`) — 머리에 번호·제목·한국어·칩, 누르면 그날 메일 카드 본문(무엇을·어떻게·실험·결과·코드). 항목명 굵게, 주소는 http(s) 만 링크.
- **버튼**: 화면당 primary 하나. 위험 동작(되돌리기)은 secondary.
- **그래프**: 축·격자는 `--line`/`--muted`, 범례는 아래, 선 끝 직접 라벨.

## 6. 금지
이모지·장식 아이콘 · 아이콘 달린 지표 타일 · 큰 숫자 하나를 영웅처럼 띄우기 · 그림자·그라데이션 · 강조색 둘 이상 ·
**DB 에 없는 지표**(0~100 "건강 점수", 도메인 분포 퍼센트 같은 시안의 자리표시 수치) · 메일에서 뺀 검증 수치("검증 통과 n/m", 2026-09-14) ·
굵기 500·600 · `Made with Streamlit`·Deploy 메뉴 노출.
